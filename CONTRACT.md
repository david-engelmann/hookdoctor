# hookdoctor contract

This contract is the executable spec for hookdoctor. Every obligation below maps to at least one named test in the test suite. An obligation is met only when its tests pass.

## Ground and probes

Hookdoctor audits the harness's hooks, blindgate audits CI's checks. Hookdoctor diffs a configured set of hooks against execution traces from session files and classifies every configured hook. It reads local files only and never reaches a network in the tool or in its tests.

The configuration probe used a synthetic settings document in the shape the Claude Code harness reads. That document carries a hooks object whose keys are event names and whose values are lists of matcher groups. A matcher group carries an optional matcher string and a hooks list and each entry in that list carries a type and a command. The probe found the events PreToolUse and PostToolUse and Stop in document order. It found a group with the matcher Bash and a group with the matcher Edit|Write and a group with an empty matcher and a Stop group with no matcher field at all. A group with no matcher field and a group with an empty matcher both stand for every subject of their event.

The matcher probe applied the harness rule to synthetic tool names. A matcher with no character outside letters and digits and underscores is a plain name and it matches only the identical tool name and the match is case sensitive, so Bash does not match bash. A matcher carrying any other character is a regular expression and it must match the whole tool name, so Edit|Write matches Edit and matches Write and matches nothing else. The empty matcher and the star matcher match every tool name.

The session probe used synthetic lines in the JSONL shape the harness writes for a session. Each line is one JSON object carrying a type and a timestamp and a session identifier. An assistant line carries message content blocks and a tool use block carries a tool name and a call identifier and an input object. A user line can carry tool result blocks and each one names the call it answers and carries an error flag. An attachment line can carry a hook record whose type is hook_success or hook_blocking_error or hook_non_blocking_error and which names a hook event and the call it ran against and a content string and an exit code. A system line with the subtype stop_hook_summary carries a hook count and hook entries naming commands and a prevented continuation flag and an output flag. The probe read all five line kinds in that shape and no other source was consulted, because no real session file may enter this repo.

The effect ground is fixed by what a trace can show. A trace shows an effect when a hook stopped work or changed work or fed output into the session. A stopped tool call and a prevented continuation are stops. A hook output that carries replacement input for the call it ran against is a change. Output is consumed when a hook record carries context text the session adds, or when a hook output names additional context, or when a stop summary says output stood. A hook that ran and left none of those marks in the trace changed nothing the trace can show, whatever it may have done outside the session.

## Slice 2 obligations

Obligation HD2-1 covers configuration ingestion. The ingester reads a settings document and walks its hooks object in document order and flattens every matcher group into one record per hook entry. A record carries the event and the matcher text or none when the group names none and the hook type and the command and a stable identifier built from the event and the group position and the entry position. An entry carrying no type field reads as a command entry. A matcher that is not a plain name is compiled while the configuration is ingested and a matcher that is not a valid pattern is refused there, whatever event it stands under and whatever any trace holds. A document with no hooks object yields no hooks and that is not an error. A malformed document and a group whose hooks list is missing and an entry with no command are refused with a hookdoctor error rather than guessed. Proven by test_config_flattens_groups_in_document_order and test_config_without_hooks_yields_no_hooks and test_malformed_config_is_refused.

Obligation HD2-2 covers trace ingestion. The ingester reads one or more session files and parses each nonempty line as one JSON object and refuses a line that is not valid JSON and a line whose object carries no type. From those lines it builds dated records in file order. A tool call record comes from a tool use block and carries the tool name and the call identifier and the timestamp and the session and the line number. A tool outcome record comes from a tool result block and carries the answered call identifier and the error flag and the result text. A prompt record comes from a user line whose content is text and not a tool result. A hook run record comes from a hook attachment whose fields name the event and the call and the hook and its content and its exit code. A stop record comes from a stop hook summary line and carries its commands and its continuation and output flags. The event of a hook run record is its event field when one stands and otherwise the part of its hook name before the first colon. A hook attachment whose fields name no event at all names no event, and the examination builds no subject from such a record, so the record stands outside the examination. Lines of any other type are counted and carried as other records and never guessed into evidence. Proven by test_trace_builds_dated_records_from_each_line_kind and test_trace_refuses_a_line_that_is_not_json and test_trace_refuses_a_line_with_no_type.

Obligation HD2-3 covers matching. A configured hook subscribes to one event. A tool call is the subject of PreToolUse and its outcome is the subject of PostToolUse and a prompt is the subject of UserPromptSubmit and a stop record is the subject of Stop and a hook run record is the subject of the event it names. A hook matches a subject when the event agrees and the matcher agrees with the subject tool name under the probed rule, where an event with no tool subject agrees with every matcher. A hook run record agrees with a hook when the event agrees and the record identifies that hook by its command or by its own name form, where the name form is the event alone or the event joined to the hook matcher or the command standing alone as the name. The event alone is the name form of a hook whose matcher is empty or missing and of no other hook, and a name form carrying one hook matcher never identifies a sibling hook on the same event. A record carrying both a command and a name form agrees only when both identify the same hook, and a record whose two identifiers point at different hooks agrees with no hook, and a record carrying one identifier is decided by that one. Proven by test_plain_matcher_is_exact_and_case_sensitive and test_regex_matcher_must_match_the_whole_name and test_empty_and_missing_matchers_match_every_tool and test_non_tool_events_agree_with_every_matcher.

Obligation HD2-4 covers a hook that ran. A hook ran on a subject when it matches that subject and the trace shows the harness reached it. A PreToolUse hook reaches every tool call it matches. A PostToolUse hook reaches a matched call only when that call has an outcome record. A UserPromptSubmit hook reaches every prompt it matches. A Stop hook reaches a stop record that names its command among its hook entries. Any hook also ran on a hook run record that agrees with it. A hook that never ran on any subject in the window did not fire in the window. Proven by test_pretool_hook_runs_on_a_matched_call and test_posttool_hook_needs_an_outcome_to_have_run and test_stop_hook_runs_when_the_summary_names_its_command and test_hook_run_record_counts_as_a_run.

Obligation HD2-5 covers the effect definition. An effect is a denial or a modification or consumed output and nothing else counts. A denial stands when a matched call carries an outcome whose error flag is set and whose text names a denial under the denial reading or names the hook command, or when a hook run record agreeing with the hook is a blocking error, or when a hook run record carries output whose decision field is block or whose permission decision field is deny, or when a stop record that names the hook has its continuation prevented. A modification stands when a hook run record agreeing with the hook carries output with replacement input for its call. Replacement input is the change by definition, because the trace carries no original input for a call, so a replacement is never compared against an original the trace does not hold and a replacement input identical to what the call would have carried still counts as a modification. Consumed output stands when a hook run record agreeing with the hook carries nonempty context content, or carries output naming additional context text, or when a stop record that names the hook says output stood. Content carried by an error record, whether a blocking error or a non blocking error, is never consumed output, because an error record reports the run itself and adds no context to the session. The denial reading of an outcome text is fixed and narrow. The text names a denial when it carries the denial word, and a text that negates its denial in the plain forms, with the word not standing before the denial word or a contracted not standing before it or the word never standing before it, names no denial at all. A text that attributes its denial to a named party, in the shape of the denial word followed by the word by and a name shaped token carrying a hyphen or a dot or an underscore or a slash, credits the hook whose command that party is when the party names a configured hook and credits no hook when the party names none, and while an attribution stands the unattributed reading does not apply. A denial text naming no party credits every hook matching the call, and that crediting is a stated limit of outcome text evidence, because the text cannot say which hook spoke and an operating system permission error standing in an outcome text reads exactly the same way. Output that is never carried by a record agreeing with the hook is not an effect of that hook, and an ordinary successful outcome is not an effect. Proven by test_denial_by_outcome_text_and_by_blocking_record and test_denial_by_output_decision_and_by_prevented_continuation and test_modification_by_replacement_input and test_consumed_output_by_context_and_additional_context and test_plain_success_is_no_effect.

Obligation HD2-6 covers the three classes. Every configured hook receives exactly one class. A hook that ran and shows at least one effect is firing. A hook that ran and shows no effect is firing without effect. A hook that never ran is silent. The class never depends on another hook and never on the order hooks stand in the configuration. Proven by test_firing_hook_with_a_denial and test_hook_that_ran_on_every_event_and_changed_nothing_is_without_effect and test_silent_hook_matched_nothing and test_every_hook_gets_exactly_one_class.

Obligation HD2-7 covers evidence. Each hook entry in the report carries the count of subjects it matched and the count of subjects it ran on and the count of effects by kind and the earliest and latest timestamp among the subjects it ran on, read as instants so two spellings of one instant are one date and the date stands spelled as the trace spelled it, or no dates when it never ran. A timestamp that cannot be read as an instant takes no part in the dates. The evidence is counted from the trace records alone and two runs over the same inputs carry the same evidence. Proven by test_evidence_counts_and_dates_come_from_the_trace and test_hook_that_never_ran_has_no_dates.

Obligation HD2-8 covers near misses. Near misses are computed only for silent hooks and are a separate list and never change a class. A traced subject in the window is a near miss for a silent hook under one of three stated edits. The name form edit stands when the matcher is a plain name and a tool name in the same event differs from it only by letter case or only by the choice between a hyphen and an underscore and a joined form. The one letter edit stands when the matcher is a plain name and a tool name in the same event is one insertion or one deletion or one substitution away from it. The event edit stands when the subject carries the paired event of the hook event, meaning PreToolUse against PostToolUse in either direction for a tool the matcher matches, or when the subject event name is the hook event name with the prefix Subagent added or removed. Each near miss names the hook and the subject and the edit that applies and the timestamp and the line and the session source the subject came from. The same subject standing on the same line of two session files yields two near misses, one for each source. A subject that matches the hook outright is never a near miss. Proven by test_near_miss_by_name_form and test_near_miss_by_one_letter and test_near_miss_by_paired_event and test_near_miss_by_subagent_prefix and test_a_match_is_never_a_near_miss_and_near_misses_change_no_class.

Obligation HD2-9 covers the window. The examination may carry a window start and a window end as timestamps. A subject counts only when its timestamp stands at or after the start and before the end, and a bound that is not given excludes nothing on its side. Timestamps and bounds are read as instants, so a record spelled with an offset stands inside a bound spelled in universal time when the instants agree, and a timestamp that cannot be read as an instant stands outside every window that carries a bound, and a bound that cannot be read as an instant is refused with a hookdoctor error. Matching and running and effects and near misses are all judged inside the window alone, so a hook whose only matches stand outside the window is silent in the window and its near misses are the subjects inside the window that nearly matched. A record with no timestamp stands outside every window that carries a bound. Proven by test_match_outside_the_window_leaves_the_hook_silent and test_near_miss_inside_the_window_is_shown_for_an_outside_match and test_unbounded_window_counts_everything.

Obligation HD2-10 covers the report format. The format name is hookdoctor-report/1. The report carries the format name and the configuration source label and the session source labels and the window and one entry per configured hook in configuration order and the near miss list. Each entry carries the stable hook identifier and the event and the matcher and the command and the hook type and the class and the evidence of HD2-7. Each near miss carries the hook identifier and the reason and the event and the tool and the timestamp and the session source and the line and the detail. The class words are firing and silent and firing-without-effect and those words are the join keys a later slice hands to the ledger as evidence. A later slice joining verdicts to the ledger keys on the event and the matcher and the command and the class word, because the stable hook identifier is positional inside one configuration document and moves when the document moves. Validation rebuilds the expected report from the same inputs and refuses a supplied report when any field differs or when a field is missing or when an unexpected field stands in the report. Proven by test_report_carries_the_format_and_one_entry_per_hook and test_report_validation_refuses_a_tampered_class and test_report_validation_refuses_tampered_evidence_and_metadata.

Obligation HD2-11 covers deterministic output and the offline boundary. The command line requires one local configuration file and at least one local session file and it writes one JSON report and one markdown report. JSON output uses sorted keys and two space indentation and one trailing newline. Entries stand in configuration order and near misses stand in a stable order by hook and timestamp and line. No output carries a wall clock time or a local filesystem path, because source labels are the labels the caller gives or the file names alone. Running the command twice on the same inputs produces byte identical report bytes. The tool reads only the local files named on its command line and a missing local input is refused with a hookdoctor error. The test suite builds every fixture synthetically and uses no network. Proven by test_cli_writes_deterministic_outputs and test_missing_inputs_are_refused and test_outputs_carry_no_local_paths.
